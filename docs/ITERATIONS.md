# Iteration log

Each round: build, review, test, then the concrete defects and gaps that drove
the next round. Findings are listed as they were found, including the ones that
turned out to be my own mistakes.

## 1 — ImageJ analysis, requirements, decoder core

Read the ImageJ pipeline down to the source (`docs/IMAGEJ_ANALYSIS.md`), wrote
the requirement table, then the TIFF reader and 45 tests against fixtures
generated by `tifffile` itself.

Two failures, both my test harness rather than the decoder: `tifffile` returns
planar pages sample-first as `(S, Y, X)` while the decoder produces interleaved
samples, and my `rgb_u8_planar` fixture was built by handing `tifffile` an
interleaved array with `planarconfig='separate'`, which it read as 64 samples of
96×3. Fixed by canonicalising in the generator and taking dimensions from the
page tags.

**Improve next:** fixtures are 64×96, so LZW never fills its 4096-entry
dictionary — code-width bumps and the KwKwK case are untested. No float64
predictor case. No tests at all for the contrast algorithms.

## 2 — Decoder hardening, contrast algorithms

Added 512×640 stress fixtures (dictionary wraparound, long runs), float64
predictor 3, uint32 predictor 2, tiled+LZW+predictor. Ported `autoAdjust` and
`stretchHistogram`, cross-checked against an independent Python transcription of
the Java.

**Found a real bug in both implementations at once:** I had rescaled 8-bit
histograms by `256/(max-min)`, so values 254 and 255 collided in one bin. ImageJ
counts byte values directly, and uses `256/(max-min+1)` for wider integers. Both
the port and the reference were wrong in the same way, which is exactly what a
cross-check is supposed to catch — but only because the reference was written
from the Java rather than from my own code.

**Improve next:** no viewer yet.

## 3 — Extension host and webview

`CustomReadonlyEditorProvider`, lazy per-page decoding with an LRU, and the
viewer surface. 105 tests passing, both bundles building.

**Improve next:** none of the webview is tested.

## 4 — Visual verification

Built `tools/render.mjs` to render a TIFF to PNG through the shipping pipeline,
and looked at the output. `debug_single_gt.tif` is a chest CT: correct at full
range, and markedly better under Auto. The Fire LUT matches ImageJ's.

Review of the code found five issues:

1. **Binary transport was unsafe.** The webview received pixels as a transferred
   `ArrayBuffer`. Structured clone of binary is not dependable across every VS
   Code transport — notably Remote-SSH, which is the whole point of this
   extension. Switched to base64.
2. `TiffDocument` imported `vscode`, so the slice and cache logic could not be
   unit-tested.
3. `stepZoom`'s reverse ladder search was convoluted and off by one after
   fit-to-window left the zoom between rungs.
4. `renderColor` treated a fourth sample as alpha, which blanks a four-channel
   scientific image.
5. No unit tests for the 8-bit mapping.

## 5 — Transport, testability, rounding

Split `SliceSource` (no `vscode`) out of `TiffDocument`, moved the wire format
into `src/wire.ts`, fixed the zoom ladder, forced alpha opaque. Added exact
`mapTo8Bit` tests fingerprinting the full 256-entry output distribution against
numpy.

**Caught by the build, not by review:** the webview started importing
`sliceSource`, which reaches `zlib` through the decoder, and the browser bundle
stopped building. That is why the wire format is its own module.

## 6 — Headless webview

Mounted the real `media/viewer.js` in jsdom with a recording canvas stub and
drove it with real messages. 25 tests: rendering byte-for-byte against the
reference pipeline, auto-contrast on open, every button, stack navigation,
keyboard, error overlay.

Three failures, all `assert/strict` rejecting cross-realm objects on identity
rather than value. Extracted the markup into `src/webviewHtml.ts` so the test
mounts the DOM the extension actually ships.

**Improve next:** not installable; no packaging.

## 7 — Packaging and the remote path

`extensionKind: ["workspace"]` so it runs on the host holding the files, a
decoded-size guard that names the setting to raise, README, `.vsixignore`,
23 KB `.vsix`. Coalesced the pixel remap into the animation frame so a slider
drag on a large image cannot queue work faster than it can be done.

## 8 — Hyperstacks and PNG export

c/z/t axes in ImageJ's page order, per-channel display ranges, and Save PNG
routed through the host because the webview sandbox blocks downloads.

**Found a real bug:** a channel shown for the first time inherited the previous
channel's range instead of getting its own, because the initialisation branch
only fired on the very first slice. A 0–100 channel viewed after a 0–5000
channel came out blank. Rewrote the decision around "has this channel been seen".

Also fixed a trap: inserting a fixture shifts the shared RNG stream and silently
invalidates the contrast reference. The two generators are now one
`npm run fixtures`, and the whole fixtures directory is generated.

## 9 — Performance and robustness

Measured on realistic data instead of guessing. A 2048² float32 slice took 75 ms
per frame to remap — about 13 fps while dragging a slider.

Profiling split it: `composeRGBA` was 34 ms, `mapTo8Bit` 12 ms, and decode was
already fine. Three fixes:

- A typed-array fast path in the decoder for uncompressed, host-endian, chunky
  data, which is what `tifffile` writes by default. Needed
  `Buffer.allocUnsafeSlow` in the reader so the offsets are element-aligned.
- Hoisted the finiteness test out of the remap. The statistics pass already
  counts NaN/Inf, so a clean image needs no per-pixel check.
- One 32-bit write per pixel in `composeRGBA` instead of four byte writes, via a
  packed LUT cached against the LUT instance.

| | before | after |
|---|---|---|
| remap 2048² (per frame) | 75 ms | **20 ms** |
| statistics 2048² | 72 ms | 41 ms |
| decode 2048² uncompressed | 100 ms | 5 ms warm |

A 120-slice, 120 MB stack opens in 1.9 ms and scrubs at 3.8 ms/slice with a 5 MB
heap — the lazy design holding up.

Added 19 robustness tests (truncation, garbage, circular IFD chains, offsets
past EOF, unsupported codecs, all-NaN images, constant images). All passed
first time; the error paths were designed in rather than retrofitted.

## 10 — Final review

Enabled `noUnusedLocals`, `noUnusedParameters`, `noImplicitOverride`,
`noFallthroughCasesInSwitch`; removed the dead code they found. Verified
rendering across float32, int16 Hounsfield, RGB, stacks and NaN images.

**197 tests, all passing.**

## Known gaps

Deliberately not built, with the reasoning:

- **JPEG, LZMA, Zstd, JPEG-2000 compression.** Each needs a codec that is either
  a native dependency or a large amount of code, which would defeat the
  "installs on any remote host with no build step" property. They fail with a
  message naming the codec and suggesting `compression='zlib'`.
- **CMYK and YCbCr photometrics.** Not used for scientific data.
- **Composite/merged multi-channel display.** Channels are viewed one at a time,
  each with its own range. ImageJ's colour-composite mode is a larger feature.
- **Editing or saving TIFF.** The editor is deliberately read-only; the whole
  design keeps the pixel data untouched.
- **Downsampling for images beyond the decode ceiling.** A page over
  `maxDecodedMegabytes` is refused rather than shown at reduced resolution,
  because a resampled image would make the pixel readout lie.
